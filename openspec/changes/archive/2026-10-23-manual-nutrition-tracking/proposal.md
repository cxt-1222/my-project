## Why

阶段 7 的第一版需要让用户把日常饮食记录沉淀为自己的数据，并以每日营养汇总查看摄入情况。目前系统尚无营养记录能力，先完成可验证的手动记录闭环，再将拍照识餐作为后续增强功能。

## What Changes

- 增加按登录账号隔离的手动营养记录，记录食物、餐次、份量及热量、蛋白质、碳水化合物和脂肪。
- 支持查看、修正和删除自己的营养记录，并按日期查看当天记录及营养合计。
- 在前端增加营养管理页面，支持选择日期、录入记录、浏览当日记录和查看汇总。
- 增加显式 PostgreSQL SQL 迁移及后端、前端测试；迁移由用户按现有流程执行。
- 本次不包含图片上传、食物识别、自动营养估算、食物数据库或目标摄入建议。

## Capabilities

### New Capabilities
- `nutrition-tracking`: 用户可维护私有的手动食物营养记录，并按日期查看记录及宏量营养汇总。

### Modified Capabilities
- 无

## Impact

- 后端：新增营养记录 SQLAlchemy 模型、Pydantic schemas、服务和认证 API 路由，并注册模型与路由。
- 数据库：新增 `kh_nutrition_record` 表及查询索引，通过显式 SQL 迁移创建。
- 前端：新增营养管理导航页、记录表单、日期筛选、营养汇总卡片和记录编辑/删除交互。
- 测试：覆盖数据校验、账号隔离、日期汇总和前端渲染/表单行为。
