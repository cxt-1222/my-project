## 3. 预览优先且可重复执行的数据导入

- [x] 3.2 实现需要明确启用的正式导入模式，支持稳定来源标识、内容哈希、各存储进度、中断后重试，并阻止未批准记录写入。
- [x] 3.3 通过现有存储链路，将动作说明和菜谱说明分别导入为可追溯来源的知识文档；不将营养事实作为 RAG 权威计算输入，并将视频作为单独媒体记录处理。所有存储及来源映射成功后才发布，导入中保持非公开。
- [ ] 3.4 仅为授权范围明确的视频建立获准的链接/嵌入/托管方式；保存媒体来源、署名和动作映射，未批准媒体不得对用户开放。
- [ ] 3.5 实现按来源版本停用/回滚，只影响映射到该版本的目录记录、媒体映射、知识文档和向量。
- [ ] 3.6 测试重复导入、中断重试、多存储部分失败、媒体许可隔离、视频与动作匹配及回滚，并确认无关知识和用户记录未被修改。
- [ ] 3.7 实现旧知识文档清理预览，逐项列出所有现存文档（包括团队/用户上传文档）及 PostgreSQL、MongoDB、Elasticsearch、Milvus、Neo4j 中对应记录数量；预览不写入或删除数据。
- [ ] 3.8 实现与导入分离且需要明确二次确认的旧知识文档清理操作；按文档 ID 删除旧文档内容和派生索引/图谱映射，不删除或重建共享集合、索引或数据库。
- [ ] 3.9 为清理增加安全与重试测试，验证未确认时零删除、部分失败后可恢复、旧文档不再可见/可检索，并确认账号、团队/权限、聊天、训练和个人饮食数据不变。
