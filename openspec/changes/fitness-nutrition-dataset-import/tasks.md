- [x] 1.1 为每个上游仓库固定完整 commit SHA、获取日期和允许读取的 JSON 文件路径；检查固定版本的实际文件结构并核实记录数量，不以图片中的数字作为依据。
- [x] 1.2 编制非视频来源清单，记录代码/动作文字和食材/菜谱许可依据、署名与用途限制及待审状态；仅将操作人员批准的本地个人测试范围标为可导入，其余隔离。
- [ ] 1.2-media 核实图片和每项视频的权利人、许可链、署名要求及允许的链接/嵌入/下载/托管方式（视频扩充阶段）。
- [x] 1.3 核实食材营养单位、每 100 克换算规则、菜谱食材数量及份量/成品量含义；记录哪些数据必须保持不完整。
- [ ] 1.4 核实动作与视频的对应关系，并由操作人员明确确认固定版本的数据和媒体来源清单；授权未确认或不包含当前展示方式的媒体保持隔离。

## 3. 预览优先且可重复执行的数据导入

- [x] 3.1 实现显式触发的固定版本远程获取器和来源锁定清单：仅请求白名单 JSON 文件，记录 commit、路径、字节数及 SHA-256；不克隆完整仓库、不执行上游代码、不请求媒体 URL。dry-run 报告输入、接受、重复、无效、隔离数量和标准化样例；正式导入校验已审阅清单中的摘要后才允许写数据库。
- [x] 3.2 实现需要明确启用的正式导入模式，支持稳定来源标识、内容哈希、各存储进度、中断后重试，并阻止未批准记录写入。
- [x] 3.3 通过现有存储链路，将动作说明和菜谱说明分别导入为可追溯来源的知识文档；不将营养事实作为 RAG 权威计算输入，并将视频作为单独媒体记录处理。所有存储及来源映射成功后才发布，导入中保持非公开。
- [ ] 3.4 仅为授权范围明确的视频建立获准的链接/嵌入/托管方式；保存媒体来源、署名和动作映射，未批准媒体不得对用户开放。
- [x] 3.5 实现按来源版本停用/回滚，只影响映射到该版本的目录记录、媒体映射、知识文档和向量。
- [x] 3.6 测试重复导入、中断重试、多存储部分失败及回滚；确认清理按精确文档 ID 执行并保留共享 Neo4j 节点。自动化测试通过。
- [ ] 3.6-media 视频许可隔离、逐项动作匹配及获准展示方式测试（按用户要求延期到视频扩充阶段）。
- [x] 3.7 实现旧知识文档清理预览，逐项列出所有现存文档（包括团队/用户上传文档）及 PostgreSQL、MongoDB、Elasticsearch、Milvus、Neo4j 中对应记录数量；预览不写入或删除数据。
- [x] 3.8 实现与导入分离且需要明确二次确认的旧知识文档清理操作；按文档 ID 删除旧文档内容和派生索引/图谱映射，不删除或重建共享集合、索引或数据库。
- [x] 3.9 为清理增加安全与重试测试，覆盖未确认/过期预览/阻断条件、部分失败后恢复、精确文档 ID 删除、共享 Neo4j 节点保留及删除结果核验。
- [ ] 3.9-preservation 对清理前后账号、团队/权限、聊天、训练计划和个人饮食记录做数据库快照对照；当前只有代码范围检查，没有清理前快照。
