## Purpose
（本能力的目的）

本能力将可追溯来源的训练动作记录导入可搜索目录和现有知识检索流程，并把已核实可展示的演示视频关联到对应动作，帮助用户理解动作。系统同时保留上游记录身份和媒体授权信息；授权未核实的媒体不得向用户开放。

## ADDED Requirements

（新增需求。固定标记说明：MUST 表示“必须”，MUST NOT 表示“不得”，WHEN 表示“当……时”，THEN 表示“则……”。）

### Requirement: 训练动作数据导入必须可预览并可重复执行
系统 MUST（必须）提供预览模式，报告输入、接受、重复、无效和隔离的动作记录数量，且不修改应用数据。导入 MUST（必须）固定上游 commit，并且只获取来源清单允许的结构化数据文件；MUST NOT（不得）要求克隆完整仓库、执行上游代码或下载/请求视频资源。预览和正式导入 MUST（必须）记录文件路径及内容 SHA-256，正式导入 MUST（必须）校验其与已审阅预览清单一致。正式导入时 MUST（必须）保留上游记录标识、数据集名称、固定的数据版本和内容哈希。重复导入同一来源版本时 MUST（必须）更新或跳过相同来源记录，而不能创建重复数据；也 MUST NOT（不得）删除无关文档、向量、训练计划或用户记录。用户查询 MUST NOT（不得）依赖实时访问上游仓库或 API。
动作或菜谱 RAG 文档在 PostgreSQL、MongoDB、Milvus、Elasticsearch、Neo4j 及来源映射写入完成前 MUST（必须）保持草稿/非公开；所有这些写入成功后才可以发布/公开。内容存储或来源映射失败时 MUST（必须）保持非公开并允许使用相同文档 ID 重试。现有权限允许作者本人查看非公开文档；其他账号 MUST NOT（不得）看到未完成导入的文档。

#### Scenario: 预览训练动作数据集
- **WHEN** 操作人员运行导入，但没有明确启用正式写入
- **THEN** 系统报告转换数量和标准化后的样例记录，不写入应用存储

#### Scenario: 从固定版本远程预览动作数据
- **WHEN** 操作人员使用来源清单中的固定 commit 运行预览
- **THEN** 系统只获取清单允许的结构化文件，报告其路径和 SHA-256，不克隆完整仓库、不执行上游代码且不请求任何视频 URL

#### Scenario: 正式导入前校验已审阅文件
- **WHEN** 远程文件无法获取，或文件 SHA-256 与已审阅预览清单不一致
- **THEN** 系统在写入应用数据前终止导入，并报告具体来源文件

#### Scenario: 重复导入同一数据版本
- **WHEN** 操作人员再次导入一个已经导入过的数据集版本
- **THEN** 每条上游动作都对应已有目录记录，不产生重复动作或知识文档

#### Scenario: 所有知识存储写入完成后才发布
- **WHEN** 系统正在向 PostgreSQL、MongoDB、Milvus、Elasticsearch、Neo4j 和来源映射写入一条动作或菜谱知识文档
- **THEN** 在所有写入成功前，该文档保持草稿/非公开；全部成功后才发布，其他账号在此之前不可见

#### Scenario: 中途失败的文档保持非公开并可重试
- **WHEN** 任一知识存储或来源映射写入失败
- **THEN** 文档保持草稿/非公开，进度指出失败存储；使用同一来源重试时复用原文档 ID，完成后再发布

#### Scenario: 拒绝格式错误的动作记录
- **WHEN** 一条来源记录没有稳定标识或有效动作名称
- **THEN** 系统将其计为无效记录，不发布也不建立索引

### Requirement: 切换到最终知识域时必须显式清理全部旧知识文档
最终运行状态 MUST（必须）只包含健身知识库和饮食知识库两个知识域；动作视频是健身知识库的关联媒体，不构成第三个知识库。新来源完成许可审查、试点导入和验收前，系统 MUST NOT（不得）清理现有知识文档。验收后，只有操作人员通过独立清理流程查看待删清单并明确确认，系统才可以删除当前所有旧知识文档，包括团队/用户上传文档，以及这些文档在 PostgreSQL、MongoDB、Elasticsearch、Milvus 和 Neo4j 中对应的内容和索引映射。清理 MUST NOT（不得）通过删除或重建共享集合/索引实现，也 MUST NOT（不得）删除用户、团队、角色/权限、聊天历史、训练计划、训练记录或个人饮食记录。普通导入、重试和来源版本回滚 MUST NOT（不得）触发全量旧知识文档清理。

#### Scenario: 新知识域通过验收后执行清理
- **WHEN** 健身和饮食数据已完成试点验收，操作人员查看清理预览并明确确认
- **THEN** 系统删除预览中列出的全部旧知识文档及其存储副本；清理完成后这些旧文档不再出现在用户列表、搜索或 AI 检索结果中

#### Scenario: 未明确确认时不清理旧知识文档
- **WHEN** 仅运行新数据导入、重试或清理预览，或操作人员未明确确认清理
- **THEN** 系统保留所有现有知识文档，不删除任何内容或索引

#### Scenario: 清理旧知识文档时保护个人和团队业务数据
- **WHEN** 操作人员执行旧知识文档清理
- **THEN** 系统不删除或重建共享 Milvus 集合，也不更改账号、团队/权限、聊天、训练计划、训练记录和个人饮食记录

### Requirement: 动作记录保留来源事实，不补造缺失字段
系统 MUST（必须）保留来源中的动作名称，以及实际存在的身体部位、器械、目标肌群、难度、动作说明、姿势提示和常见错误字段，并保留其来源信息。来源缺少的字段 MUST（必须）保持缺失，不得由模型推测补齐。标准化时 MUST（必须）保留原始值，不能用翻译后的显示名称覆盖上游事实。

#### Scenario: 导入缺少可选字段的动作
- **WHEN** 一条有效来源记录没有难度、目标肌群或动作说明
- **THEN** 目录将这些字段标记为不可用，不生成替代事实

#### Scenario: 同时保留原始名称和标准化显示名称
- **WHEN** 系统将动作字段标准化为中文显示内容
- **THEN** 记录同时保留原始来源值和带来源信息的显示值

### Requirement: 仅开放使用权已经核实的动作数据
系统 MUST（必须）分别跟踪动作文字、图片和每项视频的来源、许可状态及允许的使用方式。使用权未知或不兼容的记录 MUST（必须）保持隔离，且 MUST NOT（不得）通过目录搜索或 RAG 对用户开放。视频只有在已核实其与动作的对应关系、来源署名要求及当前展示方式（例如来源链接、嵌入播放或本地托管）获准后，才可以向用户展示；未获准下载或托管的视频 MUST NOT（不得）被复制或托管。仓库代码的许可不得被当作其中视频素材的许可证明。

#### Scenario: 搜索文字数据许可已核实的动作
- **WHEN** 用户搜索一个文字数据已批准用于本产品的动作
- **THEN** 系统可以返回该动作已有字段并标注数据来源

#### Scenario: 隔离使用权尚未确定的动作
- **WHEN** 一条记录的文字再分发许可未知或受限制
- **THEN** 系统不在面向用户的搜索和 RAG 结果中返回该记录，并向操作人员显示隔离原因

#### Scenario: 视频使用权尚未确定
- **WHEN** 动作目录中存在视频 URL，但视频使用权尚未批准
- **THEN** 系统不请求、不下载、不提供服务，也不向用户展示该 URL；预览中可以报告视频数量和待审核状态

#### Scenario: 展示已批准且准确关联的动作视频
- **WHEN** 一个动作关联的视频来源、动作匹配关系和当前展示方式均已审核批准
- **THEN** 系统按获准方式展示视频，并显示要求的来源或署名信息

#### Scenario: 视频不可播放时保留动作文字资料
- **WHEN** 已批准的视频来源暂时不可用或播放失败
- **THEN** 系统说明视频暂不可用，仍显示该动作已获准的文字资料，且不自动换成未经核实的视频

### Requirement: 动作搜索结果可以追溯来源并限定检索范围
系统 MUST（必须）支持按名称和已有动作属性搜索获准开放的动作记录。向用户显示或提供给 AI 回答的结果 MUST（必须）包含稳定来源引用，以识别数据集和来源记录。限定使用某一动作来源的 AI 回答 MUST（必须）只使用该来源中实际检索到的记录；没有检索到匹配记录时 MUST（必须）明确说明。

#### Scenario: 按动作名称查找动作
- **WHEN** 用户使用动作的原名或翻译名称搜索
- **THEN** 系统返回匹配的获准记录、已有元数据和来源引用

#### Scenario: 使用限定的动作来源回答
- **WHEN** AI 请求将依据限定为指定动作数据集或来源记录
- **THEN** 回答只引用该来源中实际检索到的信息，并将缺失字段说明为不可用

#### Scenario: 没有检索到匹配记录
- **WHEN** 动作查询没有匹配的获准来源记录
- **THEN** 系统说明该数据集中没有检索到匹配记录，不伪造来源引用
