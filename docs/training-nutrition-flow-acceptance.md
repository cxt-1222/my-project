# 训练饮食回答与目录预填验收

## 实现范围

- 用户询问训练相关饮食时，AI 只通过当前登录账号 ID 读取健身档案和最近更新的训练计划，不接受请求体指定其他用户。
- 食材和菜谱名称出现在用户问题中时，只查询已启用、许可已批准且导入来源已批准的目录记录。结构化营养值、来源、计量基准和计算依据与普通 RAG 资料分别标记。
- 菜谱营养只使用第 5 阶段已经实现的小数计算；关联食材缺失、许可不符或单位不兼容时明确标记不完整。
- 营养页面支持搜索食材或菜谱，显示来源、计量基准和不完整状态，并预填到现有饮食表单。选择目录不会调用写入接口，只有用户提交表单后才创建或更新本人记录。
- 手动录入和照片识餐流程保持原样；目录搜索是新增的只读 GET 请求。

## 自动化验证

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
node --test "tests/*.js"
```

重点测试文件：

- `tests/test_training_nutrition_context.py`：本人训练上下文、结构化目录证据、同一引用编号、缺失数据与来源限定。
- `tests/test_nutrition.py` 和 `tests/test_nutrition_photo.py`：账号隔离、手动记录、照片预览与确认。
- `tests/test_catalog.py`：许可过滤、确定性营养计算和来源限定 RAG。
- `tests/test_nutrition_tracking_ui.js`：食材/菜谱预填、缺字段、来源、计量基准和“选择不等于保存”提示。

## 人工验收

1. 登录账号 A，打开“营养记录”，依次搜索一个已批准的食材和菜谱。
2. 确认结果卡显示数据来源、版本/上游记录、计量基准和营养完整状态；隔离或不完整记录不应出现。
3. 点击“预填到饮食草稿”，确认表单出现“本次已选择 1 项”、来源和“草稿尚未保存”，但当天记录数量没有变化。
4. 修改食物名称、份量和营养值后提交，确认保存的是修改后的值，并且记录归属账号 A。
5. 取消预填，确认表单清空且没有新增记录。
6. 切换账号 B，重复查看营养记录，确认看不到账号 A 的个人记录；目录数据本身可按许可公开读取。
7. 给账号 A 保存训练计划和健身档案，向 AI 教练提问“训练后吃鸡胸肉怎么安排”。回答应说明参考了账号 A 的目标/计划；营养值只能引用结构化目录来源和计量基准，资料缺失时明确标注。
8. 使用账号 B 提问同样问题，确认不会出现账号 A 的计划、档案或饮食记录。
9. 使用“只根据知识库”限定重新提问，确认不加载本人档案、训练计划、个人记忆或网页。

## 当前限制

- 当前数据库没有计划“启用/停用”状态字段，“有效训练安排”按当前账号最近更新的计划解释；不会读取其他账号的计划。
- AI 的结构化目录补充只匹配用户问题中明确出现的已批准食材或菜谱名称。没有明确名称时不会凭模型常识编造目录记录或营养数值。
- 目录预填来源目前只用于用户检查；个人饮食记录仍保存用户最终确认的名称、份量和营养值。若后续需要审计记录与目录记录的长期绑定，应另做数据库迁移，不能静默改写既有记录。
- 当前来源许可仍待操作人员审查，未批准数据不会因为本阶段功能完成而自动开放。
