# 饮食数据计量与换算审查

## 当前状态更新（2026-10-30）

当前本地个人测试库中有 1,657 条中国食物成分记录，数据库只读核对均为 `active/approved`，计量基准均为 `per_100g`。该基准来自操作人员使用的本机审阅锁配置；原始记录仍保留，个人测试范围不代表公开或商业授权。95 条 `usda-approx` 食材、238 条菜谱和 119 个份量 profile 未导入，继续隔离。

> 固定来源：`Fission21/chisha`，commit `ac659028f37913d7f622f5598efd25957d696b2c`

## 1. 固定版本实际结构

| 文件 | 数量 | 当前确认结果 |

## 2. 食材营养字段

### 已确认

- 1,752 条记录都有 `energyKCal`、`protein`、`fat`、`CHO`、`dietaryFiber`、矿物质和维生素等数值字段。
- 1,657 条来源标记为《中国食物成分表(第6版)》，95 条标记为 `usda-approx`。
- `edible` 字段的值不是统一的 100；当前固定版本中有 1,051 条为 100，其他记录包含 80、88、97、30、65 等值。
- `food_portions.json` 的来源说明明确写出：营养素按项目收录的食物成分表每 100g 数据计算，份量用于展示估算，不替代包装营养标签。

### 必须保持的限制

- `foods.json` 本身没有逐字段的 `unit` 或 `basis` 字段。因此在没有更直接来源证据前，不能仅凭 JSON 字段名把所有营养值标记为已核实的“每 100g”。
- `edible` 不能被静默当成食材实际重量；它更像可食部比例，但该语义和适用公式仍需在转换器中显式确认。
- `usda-approx` 必须保留近似来源标记，不能与中国食物成分表记录合并为同一无来源的数据。
- 单位或基准不明确的记录只能保留原始值并标记 `incomplete`，不得由模型或转换器估算缺失单位。

## 3. 菜谱食材、份量和成品量

### 已确认

- 238 条菜谱均有 `servings`，取值为 1、2、3、4、5、6 或 8。
- 1,653 个食材明细全部是 `unit: "g"`，所有 `amount` 都是正数。
- 食材引用包含 `food.code`、`food.source` 和 `match`；其中 `match` 分为 `food`、`global`、`global-fuzzy`。
- 菜谱没有独立的成品总重量字段，也没有明确说明烹饪失水、去皮、去骨或成品重量如何影响营养值。
- 菜谱自带的 `nutrition` 字段虽然完整，但 238 条记录的 `health.confidence` 都是 `estimated`，因此不能直接作为本项目的确定性营养计算结果。

### 正式计算规则

1. 只有食材引用能稳定映射到已批准的食材记录，且该食材的营养基准已核实时，才允许计算。
2. 食材单位为克时，按明确的克数与已核实的营养基准进行比例计算；不使用相似名称的模糊匹配作为无条件依据。
3. 菜谱总营养可以按 `servings` 分摊，但只能将结果描述为“按当前配方和份数计算”；不得声称它等于烹饪后的实测每份重量。
4. 只要存在未批准食材、`global-fuzzy` 引用、缺失单位、缺失换算依据或来源许可未确认，结果必须标记为 `incomplete`，不能输出看似精确的总营养值。
5. 原始菜谱 `nutrition` 只作为待审查字段保留，不覆盖结构化确定性计算结果，也不作为 RAG 的权威数值来源。

## 4. 家庭份量参考

`food_portions.json` 的 119 个 profile 提供例如“苹果/个”“香蕉/根”等单位到克数的大小档位。该文件同时声明：

- 部分份量参考 USDA FoodData Central 家庭量口径；
- 碗、勺、把、棵等中式份量是项目按常用家庭习惯折算；
- 营养仍按每 100g 数据计算；
- 结果用于展示估算，不替代包装营养标签。

因此，家庭份量只能在页面上作为“估算换算”使用，并必须展示换算来源和“估算”标记。没有对应 profile 的单位不得自动换算。

## 5. 结论与导入门槛

结构化目录和转换器已经实现；当前只在本地个人测试范围内启用了中国食材记录。其余来源继续隔离。后续扩展仍必须保留：

- 原始营养值、原始来源和原始 `edible` 值；
- 明确的计量基准字段，例如 `per_100g`、`recipe_ingredient_g` 或 `household_estimate`；
- 食材引用状态、单位兼容性和计算完整性；
- 菜谱份数与“没有成品总重量”的限制说明。

未经批准的来源不进入用户查询、RAG 或营养计算接口。当前已批准的中国食材目录仍通过结构化查询提供来源和 `per_100g` 基准，不将菜谱营养值用作权威计算依据。
